# COCOSiL V2 — F3 統合レポート システム要件定義書

> 4体系を1つの立体的な自己像として届ける — UXシーケンス「安心→分析」の中核実装
> V2の核心フィーチャー（F3.1〜F3.5）のシステム要件をF3専用にまとめたもの

---

## システム概要

F3「統合レポート」は、COCOSiL V2の全UX体験の中核をなすフィーチャー群である。F2で収集した4体系診断結果（星座・動物性格診断・六星占術・MBTI）をAI（OpenAI）が統合し、パンチャ構造（4+1=5）の論理的必然によって「1つの立体的な自己像（識）」を生成する。単なるラベルの羅列ではなく、「なぜ自分はこうなのか」が構造として腑落ちする体験が目標である。

技術的には、Vercel OG（Satori）による縦長（1024×1792）構造化レポートをサーバーサイドで即時生成し、文字崩れゼロを保証する。レポート表示直前に必ず「安心（F3.2）」フェーズを挿入し、「結果＝評価」から「結果＝地図」への認知転換をユーザーに保証する。診断を終えた直後の新規ユーザー（ペルソナA：佐藤麻衣）を主対象に、初回体験で7日以内再訪率30%以上を実現する設計とする。

5サブフィーチャーはPhase 1（F3.1〜F3.4）とPhase 3（F3.5）に分割して実装する。

## 機能要件

### F3.1: レポート生成エンジン

| ID | 要件 | 優先度 | 詳細 |
|----|------|--------|------|
| F3.1.1 | LLMによるコンテンツ生成 | 必須 | MBTI診断完了（またはスキップ確定）をトリガーに、4体系診断データをOpenAI APIに送り、バックグラウンドでレポート本文を生成する。タイムアウト30秒。失敗時はフレンドリーエラー＋リトライ導線 |
| F3.1.2 | Vercel OG（Satori）でのレポート整形 | 必須 | 生成済みコンテンツをReactコンポーネント（og-image.tsx）に流し込み、1024×1792の縦長PNGをサーバーサイドで即時生成。文字崩れゼロを保証 |
| F3.1.3 | 4体系統合考察セクション（必須1件以上） | 必須 | レポートに星座・動物・六星・MBTIの4体系すべてを横断する統合考察セクションを1つ以上含む。4ラベルの羅列のみのレポートは不合格（AC-1） |
| F3.1.4 | 「大切な人との関係ヒント」セクション（必須1件以上） | 必須 | 設計中枢 原則③（Self-Knowing for Better-Relating）の実装。対人関係に言及するセクションを1つ以上含む（AC-2） |
| F3.1.5 | Supabase Storageへの永続化 | 必須 | 生成PNGを `user-reports` バケットに `${user_id}/${uuid}.png` で保存。RLS policy（`user_id = auth.uid()`）を必ず適用 |
| F3.1.6 | Markdown+CSSフォールバック | 必須 | Vercel OG生成失敗時は静的Markdown+CSS形式でレポートを表示。ユーザーに生成失敗を悟らせない設計 |
| F3.1.7 | 全セクション閲覧・F3.4/次アクション導線到達 | 必須 | レポートの全セクションがスクロールで閲覧可能。末尾にF3.4アンケートと次アクション（F4チャット）導線を配置 |

### F3.2: 「安心」フェーズ

| ID | 要件 | 優先度 | 詳細 |
|----|------|--------|------|
| F3.2.1 | F3.1完了直後・表示前への必須挿入 | 必須 | F3.1レポート生成完了→表示直前の「無防備ゾーン」に必ず挿入。スキップ不可（D5）。スキップボタン・設定を設けない |
| F3.2.2 | 15秒以内完了（並行生成時最大30秒） | 必須 | 自動完了（15秒）またはCTAタップで完了。OpenAI生成がF3.2と並行している場合は最大30秒待機 |
| F3.2.3 | 呼吸アニメーション（4〜8秒） | 必須 | CSSアニメーションで実装。gpt-image-2等の外部依存なし（Phase 1完結） |
| F3.2.4 | 固定テキスト（60字以内） | 必須 | 「あなたの結果が揃いました。読む前に、ひとつだけ。」（60字以内）。言語設計準拠・禁止語0%（占い・鑑定・当たる・霊感・霊視） |
| F3.2.5 | AIサブテキスト（3要素・100字以内） | 必須 | 承認・脱判定化・招待の3要素を含む。「地図」メタファーで「結果＝評価」→「結果＝地図」の認知転換。えんまさ設計（Gate 2対象） |
| F3.2.6 | CTA「読んでみる→」（Thumb Zone内） | 必須 | 双方向対話なし・AIがユーザーに質問しない・インタラクションはこのCTAボタン1つのみ |
| F3.2.7 | F1.3（共感フェーズ）との明確分離 | 必須 | ActiveモードのF1.3と、Receptiveモードの F3.2は明確に区別。テキスト入力・選択肢・スワイプなし |
| F3.2.8 | 再訪時アニメ短縮＋テキスト変更 | 重要 | 2回目以降の訪問時はアニメ短縮＋別テキストで摩擦を低減 |

### F3.3: 「しっくりきた」マーカー

| ID | 要件 | 優先度 | 詳細 |
|----|------|--------|------|
| F3.3.1 | セクション単位のマーカー配置 | 必須 | レポートの各セクションに「しっくりきた」マーカーボタンを配置。セクション単位で個別にマーク可能（D6） |
| F3.3.2 | 1タップで記録・解除（可逆） | 必須 | マーク／マーク解除がそれぞれ1タップで完了。テキスト入力・確認ダイアログなし。タップ時に視覚フィードバック（チェック等）表示 |
| F3.3.3 | DBへの記録とF4.3/F5.3への参照提供 | 必須 | マークした項目（セクションID・テキスト等）をSupabase DBに記録し、F4.3（過去気づき参照）・F5.3（振り返り）から参照可能にする |
| F3.3.4 | 未マーク時の否定形表示禁止 | 必須 | 残件数・「0件です」等の否定形を一切出さない（AC-3）。設計中枢 原則② |
| F3.3.5 | UIテキスト（チェックラベル等）の言語設計準拠 | 必須 | 「しっくりきた」「これ自分だ」等のラベルはえんまさ設計（Gate 2対象） |

### F3.4: 満足度アンケート

| ID | 要件 | 優先度 | 詳細 |
|----|------|--------|------|
| F3.4.1 | レポート末尾への配置 | 必須 | レポートを末尾までスクロールして読了した後、自然に到達できる位置に配置 |
| F3.4.2 | 5段階評価（1タップ選択送信） | 必須 | 5段階の評価を1タップで選択し送信。送信ボタン不要（タップ＝送信）が理想 |
| F3.4.3 | 自由記述（任意・空でも送信可） | 必須 | ひとことメモを任意入力。空白のまま送信可能 |
| F3.4.4 | スキップ導線（非強制） | 必須 | 未回答でも後続機能（F4チャット等）に進めるスキップ導線あり（D7）。「声を届けた」感覚を設計するが強制しない |

### F3.5: レポート再生成

| ID | 要件 | 優先度 | 詳細 |
|----|------|--------|------|
| F3.5.1 | 30日経過ゲート | 必須 | 再生成ボタンは前回生成から30日経過後にのみ有効化。月1回上限を超える再生成は不可。未経過時はボタン無効＋次回可能日を表示 |
| F3.5.2 | 課金プラン限定ゲート（D4） | 必須 | 無料プランからの再生成試行時は生成せず「有料プランで月1回再生成できます」の誘導表示。言語設計準拠・禁止語0% |
| F3.5.3 | 蓄積データ反映型コンテキスト注入（D3） | 必須 | 再生成時は前回生成以降のF4チャット履歴・F3.3マーカー記録・F5アクション記録をプロンプトに注入し「今の自分」を反映した更新版を生成 |
| F3.5.4 | 蓄積データ乏しい場合の破綻防止 | 必須 | 蓄積データが少ない場合もプロンプトが破綻せず最低品質のレポートを生成できる。空データ時のフォールバックロジックを用意 |
| F3.5.5 | 旧レポートのDB保持（比較UIなし） | 重要 | 再生成後、旧レポートはDBに保持するが履歴比較・差分表示UIは提供しない（Phase 3スコープ外） |
| F3.5.6 | 生成・保存フロー | 必須 | F3.1の生成フロー（LLM→Vercel OG→Supabase Storage）を再利用。課金状態検証→月次枠消費→生成→保存の順に処理 |

> **優先度の凡例**: 必須（MVP相当）/ 重要（なくても動くが価値が毀損）/ 任意（あれば嬉しい）

| パフォーマンス | 「しっくりきた」マーカーのタップレスポンス | **100ms以内** | 読みながら反射的にタップする超低摩擦設計の前提。遅延があると摩擦化する |

| セキュリティ | 入力値バリデーション | APIルート入力値はZod（`zod/v4`）スキーマで全検証 | SQLインジェクション・不正データ注入防止 |
| 信頼性 | Vercel OG生成失敗時フォールバック | Markdown+CSS静的レポートへ即時切替 | 外部API障害時もユーザー体験を継続。gpt-image-2は文字レイヤー非担当なので影響なし |
| 信頼性 | OpenAI API障害時 | フレンドリーエラー＋リトライ導線表示 | エラーオブジェクトをそのままクライアントに返さない（Gate 1要件） |
| ユーザビリティ | 言語設計準拠 | 禁止語（占い・鑑定・運勢・当たる・霊感・霊視）0% | `lib/constitution/banned-words.ts` が唯一の正リスト |
| ユーザビリティ | UXシーケンス順守 | 共感→安心→分析→行動の順序を破らない | `lib/constitution/ux-sequence.ts` が正。F3.2スキップ不可の根拠 |
| スケーラビリティ | Supabase Storage使用量 | 0.5GB上限（無料枠）以内で運用 | テキストデータ中心・積極的アーカイブ戦略で管理（AGENTS.md §4） |
| 対応環境 | ターゲットデバイス | スマートフォン（iOS/Android）ブラウザ優先 | ペルソナAの主要デバイス。Thumb Zone内CTA設計の根拠 |

## 開発ロードマップ

### Phase 1: F3 MVP Core（F3.1〜F3.4）
**目的**: V2の核心体験「安心→分析（レポート）」を初回ユーザーに届ける。PMF検証（7日以内再訪率30%、レポート満足度4.0/5.0）に必要な最低限の機能を揃える。

- F3.1: LLMコンテンツ生成→Vercel OGレポート生成→Supabase Storage保存 API実装（TSK-API-002）
- F3.1: 統合レポートプロンプト設計（えんまさ担当・Gate 2対象、TSK-PROMPT-001）
- F3.2: 「安心」フェーズUI実装（スキップ不可・呼吸アニメ・固定テキスト＋AIサブテキスト・CTA）
- F3.2: AIサブテキストプロンプト設計（えんまさ担当・Gate 2対象）
- F3.3: 「しっくりきた」マーカーUIおよびDB記録実装（F3.1完成後）
- F3.4: 満足度アンケートUI実装（F3.1末尾に同梱）
- F3.4: KPIダッシュボード（F9.3）への集計接続

### Phase 2: F3 継続性検証（F3.3利用率）
**目的**: F3.3マーカーの利用率10%以上を検証し、未達の場合は3スプリント以内に再設計する。F4.3/F5.3との連携を確認する。

- F3.3利用率の計測セットアップ（F9.3 KPIダッシュボード）
- F4.3（過去気づき参照）へのマーカーデータ提供の実装
- F5.3（振り返り）へのマーカーデータ提供の実装
- F3.3マーカー利用率10%未達時の再設計（条件付き）

### Phase 3: F3.5 レポート再生成（課金機能）
**目的**: F7（Stripe課金）実装後、蓄積データを持つ継続ユーザーに「生きた地図」の更新体験を提供する。副軸C（体験深化）の中核を実現する。

- F7（Stripe課金）への依存解消を確認
- F4/F3.3/F5のPhase 1〜2蓄積データのプロンプト注入設計（TSK-API-009）
- 再生成API実装（30日ゲート・課金ゲート・蓄積データ反映）
- 再生成プロンプト設計（えんまさ担当・Gate 2対象）
- F3.5 UI実装（再生成ボタン・次回可能日表示・有料誘導）
