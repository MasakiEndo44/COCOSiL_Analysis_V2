# Goal: F3統合レポート UI/UX改善 — テーブル構造化と"自己との出会い"化

> **本書の位置づけ**: えんまさの議事録（独り言）を起点に、expert-misaki-discussion で方針を発散→収束させ、goal-grill で Vision/Outcome/Eval を確定した受け入れ基準。実装の単一の真実とする。
>
> **設計3原則**（議論で確定 / `docs/discussions/20260602_議論ログ_F3統合レポートUI改善.md`）:
> - ① **Scan the Mirrors, Read the Self.** — 観察素材（4体系・5軸）はテーブルで一望、観の結論（統合像）は文章で読ませる。器の形が思想を裏切らない。
> - ② **Specificity Dispels Fog.** — 「慎重です」でなく「こういう場面でこう動きがち」。行動シーン(A)と矛盾の多面性(D)で解像度を上げる。Specificity = Shareability。
> - ③ **Compare Without Ranking.** — テーブルは比較=慢（三毒）の温床。セルは"現れ方"記述に徹し評価語禁止。マーカーは断片でなく統合像に宿す。

---

## Vision

### 問題

統合レポートの「分析」フェーズが**"自己との出会い"に昇華していない**。4体系・統合像がプロセ文の羅列で表示され、(a) 主要な診断結果をスキャン・対比できず認知負荷が高い、(b)「はじめに/おわりに」の定型文が画面を占有、(c)「で？結局どういう私？」を消す具体性（行動シーン・多面性）が不足。結果、ユーザーは最後まで読まずスクショして離脱する。

根本診断（議論Turn1）: これは情報整理の問題でなく、止観の「止＝反応を止める」で留まり「観＝パターンを命名する」に到達していない問題。テーブル化は、バラバラの4枚の鏡を1人の像に結ぶ"観"の操作を構造が代行する意味を持つ。

### ユーザー

COCOSiL V2 のエンドユーザー（25-35歳の若手社会人）。診断を終えて統合レポートに到達した人。職場・恋愛・家族の対人関係で消耗し「自分も相手もなぜそうなるか分からない」無明の解消を求める層。SNSシェアの起点にもなる。

### 代替手段

現状の羅列レポートを自力で読み解くしかない。4体系がバラバラに提示されるため、頭の中で統合しようとして挫折し、スクショだけ撮って閉じる（＝統合は起きない）。あるいは他の占い/診断系サービスに流れる。

### 6ヶ月後の成功像

レポートを開いたユーザーが「材料（4体系・5軸）を一目で対比 → 統合像で"これが私だ"と腑落ち → 関係ヒントで行動へ」という止観の流れを最後まで辿り、"これ私すぎる"とシェアしたくなる——分析が"自己との出会い"として機能している状態。

## Outcome

### 何が変わるか

統合レポートの主要診断結果（4体系・5観察軸）が構造化テーブルで一目で対比可能になり、統合像に行動シーン・多面性の具体性が加わって「自分ごとの発見」が生まれ、冗長定型文（はじめに）が除去されて認知負荷が下がる。画面内HTMLが主役化し、OG画像はシェアカードに降格する。

### 測定方法

- **一次（合格判定の主軸）**: えんまさのプレビュー手動確認 — "これ私すぎる"の腑落ち主観一致・止観シーケンスの垂直再現。
- **二次（定量）**: PMF基準の7日以内再訪率30%以上、満足度アンケート（SatisfactionSurvey）スコア、（将来）レポート最下部到達率・シェア率。

### 期限

なし（継続的）。厳密な日付期限は設けず、えんまさのプレビュー承認をマージ条件とする（アトミック確認ループ: 型チェック＋ビルド＋動作確認）。

### 最低ライン（下回ったら失敗）

以下のいずれかに該当したら失敗とみなす:
- (a) 禁止語（占い等）が1語でも混入
- (b) テーブルのセルに評価語・優劣表現が出て三毒（慢）を増幅
- (c) 統合像をテーブル化して観の山場が平坦化
- (d) 止観の垂直順（共感→分析→行動）が崩れる
- (e) えんまさが腑落ち主観一致を却下

## Eval criteria

- [ ] **構造化出力**: LLMが構造化JSON（`four_lights: {system,label,reading}[4]` / `integration: {axisKey,axisLabel,manifestation}[5]` ＋ `core` 文章）を返し、`opening` は廃止されている。
- [ ] **止観の縦順レンダリング**: 画面が catchphrase→4体系テーブル→5軸テーブル→統合像（文章・accent）→関係ヒント→おわりに（ベタ打ち）の縦順で表示され、4体系=4行・5軸=5行のテーブルがモバイル縦長で崩れない（軸名はモバイル短縮ラベル）。
- [ ] **具体性とマーカー配置**: 統合像/関係ヒントに行動シーン描写(A)と多面性(D)が含まれ、KnowMarker はその文章ブロックのみに付く（テーブル行には付かない）。
- [ ] **失敗ケース（これが起きたら壊れている）**: 5軸テーブルがモバイルで軸名カラム折り返し崩壊／LLMが配列でなく自由文を返してテーブルがレンダリング不能／統合像 `core` が空でファーストビューに"自分ごとの発見"が出ない。

**確認方法**: 両方。
- 機械: `pnpm typecheck` ／ `pnpm build` ＋ プロンプト単体テスト（禁止語0%・評価語チェック・配列構造のスキーマ検証）。
- 人間: えんまさがプレビューURLで腑落ち主観一致・止観順・テーブル表示崩れを手動確認（Gate2: プロンプト/診断ロジック変更につき AI応答サンプル3件添付）。

**劣化検出**: `lib/prompts/__tests__` の禁止語・評価語・配列構造テストをCIに常設（Prompt as Code）。加えて satisfaction survey スコアと7日再訪率のモニタリングで体験劣化を検知。テストコマンド未整備は HARNESS_HEALTH.md §G1 の既知課題として記録。

## 実装メモ（議論Turn5の具体アクション）

1. **schema/プロンプト改訂（Layer2）**: `four_lights` を `{system,label,reading}[]` の4要素配列、`integration` を `{axisKey,axisLabel,manifestation}[]` の5要素配列＋ `core`（識の文章）に分離。`opening` 廃止。
2. **行動シーン注入**: `integration` の各 manifestation に「具体的な場面描写を1つ含める」をプロンプト制約に追加（方向A）。`core` に「食い違う体系を多面性として結ぶ」を必須化（方向D）。光と影(B)は肯定ファースト＋傾向表現の条件付き。
3. **UI再構築**: `app/diagnosis/result/page.tsx` を上記の縦順に。軸名は短縮ラベル（からだ / 感じ方 / 考え方 / 動機 / 人との距離）。
4. **マーカー再配置**: KnowMarker を統合像・関係ヒントの文章ブロックのみに。テーブル行から除去。
5. **OG画像の降格**: `og-builder.tsx` は catchphrase＋統合像の核だけのシェアカードに簡素化。フルレポートをPNGに詰めない。
6. **検証**: 禁止語0%テスト・三毒（評価語）チェック・`pnpm typecheck`／`build`、えんまさプレビュー確認。
