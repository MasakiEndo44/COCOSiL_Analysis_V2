# Goal: F3 レポート揺らぎ抑制と自画像の核（ProfileCore）

> **本書の位置づけ**: 2026-06-02 ユーザーテスト（亀井さん評価）で顕在化した「**AIレポートが毎回揺らぐ**」問題を起点に、F3 統合レポート＋共感AIチャットの揺らぎ抑制・自己像の一貫提示・UX構成を Vision / Outcome / Eval の3層で確定する。`f3-keyword-tree-integration.md`（Tree of 4, Harvest 1.）が「4体系をどう統合するか」を定めるのに対し、本書はその統合結果を含む診断値を「**揺らがず・出自を持って・三毒を煽らず提示する**」レイヤーを定める。
>
> **設計原則5箇条**（議論で確定）:
> - ① **Score Once, Narrate Freely** — 数値は diagnostics 層で一度だけ確定、prompts 層はそれを語るだけ
> - ② **Variation Without Randomness** — 語り口の多様性は temperature でなく Core 由来の決定論的選択で
> - ③ **Append-Only Self** — ProfileCore は追記専用・version 凍結、過去レポートは旧 Core で再現
> - ④ **The Core is Free, The Depth is Earned** — 確定核は無料で一貫提示、課金は核の射影範囲（深掘り・行動提案）に限定
> - ⑤ **Reproducible Evidence Dispels** — 再現する根拠だけが無明を晴らす（決定論化は Dispel 原則の実装）

---

## Vision

### 問題

2026-06-02 のユーザーテストで、同一生年月日・同一MBTIタイプでも、レポートのタイトルや論調が「リーダー寄り／サポーター寄り」で**毎回ぶれる**現象が確認された。亀井さんは「同じ私なのに結果が違うと、どっちが本当の私か分からず信用できない」と評価した。

根本原因は二層に分かれる（議論 Turn 1）:

1. **技術的根因** — 決定性が設計に組み込まれていない三層問題:
   - LLM層: temperature / seed を固定せず生成ごとにサンプリングが走る
   - プロンプト層: 「リーダー寄り／サポーター寄り」の判定基準が言語化されずモデルの自由度に委ねられている
   - 最深部: 4体系の重み付けが算命学:MBTI≈1:1 と曖昧、かつ MBTI の A/T 軸が欠落し、**入力ベクトルそのものが一意に定まっていない**
2. **体験的根因** — ユーザーが「自分の像を結べていない」。揺らぎが致命的なのは数値が動くからではなく、ユーザーが自己像を検証する**基準点（錨）を持てない**ため。揺らぎはバーナム効果を「どれが本当の私か」という不信へ反転させる。

この二つは同じコインの裏表で、**「観測軸が定義される前に LLM へ丸投げしている」**という一つの構造に帰着する。これは設計中枢「Dispel, Don't Decorate」に反する——根拠が再現しない分析は無明を晴らせない。

### ユーザー

- **エンドユーザー**: F3.1ペルソナA「佐藤 麻衣（28歳・IT企業CSマネージャー）」／テスト評価者・亀井さん（さよっぴ）に代表される 25-35歳若手社会人。「占いとは言いたくないが自分を構造的に理解したい」層。
- **直接の運用ステークホルダー**:
  - **ヒラメ**: `lib/diagnostics/` のスコア確定ロジック・ProfileCore 型・A/T 軸統合・重み係数の実装、`lib/prompts/` の翻訳プロンプト実装（Gate 1）
  - **えんまさ**: レポート文面・用語・弱み提示トーンの意味設計と承認（Gate 2）
  - **まあみ**: 用語ヘルプ(?)・分布グラフ・「次は何を知りたい？」分岐の UI 実装

### 代替手段（現状）

- 現状の F3 実装: 4体系ラベル＋診断値を LLM に渡して「レポートにして」と頼む → temperature 既定値で毎回文面と論調が揺らぐ。揺らぎ＝品質が運頼み。
- A/T 軸なし: 16型のままで「自己主張型(A)／慎重型(T)」が判定されず、サポーター/リーダーの分岐が一意に決まらない。

### 6ヶ月後の成功像

**「同じ入力なら何度生成しても自己像の核（キャラ名・5軸スコア・32型）が一字一句ぶれず、ユーザーが『これが私』と錨を得て、弱みも“行動のヒント付き”で受け取り、共感AIチャットへ自発的に進む状態」**

機械的には: 同一入力での再生成において **ProfileCore の確定フィールド一致率 100%**、レポート文面の核要素（キャラ名・強み2・弱み1の主旨）一致率 100%、揺らいでよいのは語り口の修飾のみ。

## Outcome

### 何が変わるか

**① 決定論スコア核 `ProfileCore` の確立（Source of Truth）**
`lib/diagnostics/` が、診断入力から **不変の確定スコアオブジェクト**を一度だけ算出する。LLM・チャット・課金境界はこれを**読み取り専用で参照**する放射構造になる。

```
ProfileCore {
  axes: { /* F3.1 観察軸5軸の数値スコア 例 leadership: 72, support: 38, ... */ },
  type32: "INTJ-A",            // MBTI 16型 × A/T軸 = 32型
  characterLabel: "慎重な調停者",  // 形容詞＋名詞。Core から決定論導出（自己像の錨）
  weights: { sanmei: 0.4, mbti: 0.6 },  // 重み係数を明示（MBTI寄りへ再調整）
  johariBlindspots: [ /* core数値から決定論導出した「自覚しにくい強み」 */ ],
  distribution: { /* 「同タイプ内傾向／設計上の理論分布」出自を明示 */ },
  seed,
  version                      // Core schema version
}
```

**責務分界線**: `lib/diagnostics/` ＝「**数値を決める**」／ `lib/prompts/` ＝「**決まった数値を語る**」。語り手（LLM）は数値を一切再計算しない。

**② 揺らぎの根絶（数値層で殺す）**
- A/T 軸を簡易診断に追加し 16→32型へ解像度を上げ、入力ベクトルを一意化
- 重み係数を明示化（算命学:MBTI ≈ 1:1 から **MBTI寄り**へ再調整、例 0.4:0.6）
- LLM 翻訳層は **temperature=0／seed 固定**
- 語り口の多様性は temperature でなく **Core の hash から有限集合を決定論的に選択**（低 temp 依存は揺らぎの裏口侵入なので禁止）

**③ UXシーケンスに沿ったレポート構成（反応でなく観察へ）**

| フェーズ | 配置要素 | 根拠 |
|---|---|---|
| 🔴 共感 | 冒頭にキャラ名（形容詞＋名詞）を提示 →「そういう私、いる」 | 自己投影の錨を最初に置く |
| 🔴 安心 | 強み2を先に提示、弱み1は「ほろ苦い但し書き」で後置（強み2:弱み1） | 順序を逆にすると瞋（防衛）が起き観察に入れない |
| 🔴 分析 | ジョハリの窓（盲点）＋ 🟡分布比較を開く | 安心の後だから防衛されず俯瞰を受け取れる観察装置 |
| 🔴 行動 | 「次は何を知りたい？（強み／弱み／意外な一面）」分岐 → 共感AIチャット誘導 | みさき実需「なんで同じ失敗する？」を受ける入口 |

**④ 弱みの提示原則**
弱み1は必ず「**だからこの場面では〇〇するとラク**」という行動の出口とセット。人格否定（お前はダメ）でなく状況依存（この条件で出やすい癖）として提示する。出口なき弱みは三毒（瞋）を煽る装飾。

**⑤ 出自を持つ座標（Dispel 担保）**
ジョハリ盲点・分布比較は **LLM 推定や捏造データを使わず**、ProfileCore の数値から決定論的に導く。分布は「一般分布」と詐称せず「**同タイプ内傾向／設計上の理論分布**」と出自を正直に明示する。UI 上の他者視点表現は「決めつけ」でなく「**こう見られがちかも**」とする（みさき要望）。

**⑥ 課金境界（Dispel not Decorate を守る二層）**
- **無料・固定**: 自己理解の核（キャラ名・5軸・32型・強み2弱み1・基本ジョハリ）
- **完全版（課金）**: 同一 Core の射影拡張（同タイプ内の個別深掘り・相性・行動提案の具体化）
- 自己理解の核を人質にした課金は NG。**腑落ち前に課金導線を出さない**（みさき: 腑落ちゼロでの課金導線は「一生払わない」）

**⑦ 用語平易化＋ヘルプ**
「体→身体気質エネルギー」「動機→原動力／やる気の源」等の平易化マップを整備し、各項目に ヘルプ(?) ツールチップで用語解説を付与する。

### 測定方法

**🤖 機械判定（Eval / CI）**
- **再現性（Positive）**: 同一入力での再生成 N 回で ProfileCore 確定フィールド一致率 = 100%
- **核一致（Positive）**: レポートのキャラ名・強み2・弱み1主旨の一致率 = 100%（揺らいでよいのは修飾語のみ）
- **両面比率**: 強み:弱み ≈ 2:1 を満たす
- **弱みの出口（Positive）**: 各弱み記述に行動提案がセットされている率 = 100%
- **出自明示（Negative）**: 「一般分布」「平均」等の出自不明な母集団断定が 0 件、禁止語彙 0 件
- **三毒ガード（Negative）**: 弱み記述に人格否定表現が 0 件

**🧑 人間判定（えんまさ Gate 2）**
- 「占いじゃなく観察された」感覚の主観一致
- 弱み提示が「甘じょっぱく・ほろ苦い」受容トーンに収まっているか
- UXシーケンス（共感→安心→分析→行動）の順序遵守

## 実装アクション（優先度順 / 議論 Turn 5）

1. **【最優先 / `lib/diagnostics/`】** キャラ名（形容詞＋名詞）を ProfileCore から決定論導出する関数を実装。32型×A/T軸から一意マッピング。揺らぎ撲滅の核。→ Gate 1 ＋ Gate 2（診断結果サンプル3ケース）
2. **【`lib/diagnostics/`】** ジョハリ盲点・分布比較を LLM 推定でなく core 数値から導く算出ロジックを追加。出自をメタデータ保持し「同タイプ内傾向」と正直表示。→ Gate 1 ＋ Gate 2
3. **【Gate 2 / `lib/prompts/`】** レポート文面プロンプトを作成。共感(キャラ名)→安心(強み2先・弱み1後置)→分析の順序を構造固定、弱みは行動の出口とセット化、temperature=0／seed 固定。→ AI応答サンプル3件（before/after）添付
4. **【Gate 2 / `lib/prompts/`＋UI】** 用語平易化マップ（体→身体気質エネルギー等）＋ヘルプ(?)文言を整備。→ language-design スキル準拠・プレビューURL＋文言diff
5. **【UI / まあみ】** 「次は何を知りたい？」分岐と共感AIチャット誘導を実装。課金境界を核の外に置き、腑落ち前の課金導線を出さない。→ プレビューURL＋フロー図

> **A/T軸の入力設計（補足）**: 簡易診断に A/T 判別設問を数問追加する（みさき「正確になるなら全然答えたい」）。設問追加は UX フロー変更を伴うため Gate 2 対象。
