# Goal: F3.1 4体系統合アルゴリズム — Tree of 4, Harvest 1.

> **本書の位置づけ**: F3.1 レポート生成エンジンの「4体系統合」をLLMにどう生成させるかのアルゴリズムを Vision/Outcome/Eval の3層で確定する。既存 `docs/output/F3/F3_integrated-report_features.md` の AC-1（統合性）を機械判定可能な仕様に具体化する基礎。
>
> **設計3原則**（議論で確定）:
> - ① Common Axis, Not Common Word — 観察軸を先に固定し、その上に4体系を載せる
> - ② Thickness = Convergence, Not Repetition — 「太い幹」は語の重複ではなく軸の収束
> - ③ Harvest, Don't Hallucinate — LLMはツリー外の創作禁止

---

## Vision

### 問題

既存 F3.1 ドキュメントは AC-1「4ラベル羅列だけは不合格／統合考察1セクション以上」を宣言したが、**その「統合」をLLMにどう生成させるかのアルゴリズムが未定義**で、現状のプロンプト設計では LLM が高確率で並列の羅列に逃げる。

根本問題は「**並列を統合と呼んでしまっている認識の罠**」（議論Turn1診断）。4体系をJSON化して並べても、共通接続点（hub node）がないため LLM は並列を並列のまま返す。

本タスクは「**Tree of 4, Harvest 1.**」設計——共通観察軸（パンチャ構造翻訳版5軸）を root とし、その上に4体系の枝を接続、太さ=接続体系数で収束を検出、3層分類（整合・補完・矛盾）でレポートを構造化——をF3.1に実装することで、設計中枢§2.3パンチャ構造の論理的必然をプロンプト技法として実現する。

### ユーザー

**エンドユーザー（最終受益者）**:
- F3.1ペルソナA「佐藤 麻衣（28歳・都内IT企業CSマネージャー）」プライマリー
- "占いとは言いたくないが、MBTIや星座で自分のことが分かる体験をしたい層"
- 「並列の4ラベル」では満たされない「**なぜ自分はこうなのか**」の構造的理解を本タスクが届ける

**直接の運用ステークホルダー**:
- **ヒラメ**: 仕様に従った実装（`lib/diagnostics/integration/` のツリー生成・収穫ロジック・プロンプト・テスト）
- **えんまさ**: ドメイン知識生成（Deep Research）＋仕様化（詳細要件定義書 §4.3 への織り込み）＋品質判定（Gate 2）
- **白石的な象徴体系専門家**: アドバイザー位置（必須ではなく必要時に相談）

ペルソナBの田中健太は F3.5（再生成）の主ペルソナで、本タスクでは副次的受益者。

### 代替手段

**現状の代替手段（COCOSiL外）**:
- MBTI単体サイト → ラベル止まりで「なぜ」が埋まらない
- 星座・干支占い断片読み → スピリチュアル臭で知的層が離脱
- 複数診断サイト巡回 → 認知負荷高・体系間矛盾を解消する枠組みなし
- 占い師に対面 → スピリチュアル領域でターゲット回避／コスト高

**F3.1既存実装（本タスクなし状態）**:
- LLMに4ラベル渡して「統合してね」のプロンプト → 9割の確率で並列羅列に逃げる（議論Turn1診断）
- AC-1「4ラベル羅列不合格」を宣言だけで担保できず、レポート品質が運頼みになる

### 6ヶ月後の成功像

**「F3.1レポートを読んだユーザーが『占いじゃなくて観察された』と感じ、整合・補完・矛盾の3セクションのうち少なくとも1つに F3.3『しっくりきた』マーカーを付け、F4チャットで harvest キーワードを自発的に引用してくる状態」**

「Tree of 4, Harvest 1.」設計が、ユーザーの認知（ラベル→構造的自己像）・行動（マーキング・引用）・継続意欲（7日内再訪）の3面で機能している状態。機械的には harvest.representative_keywords の語が F4チャット発話に出現する割合 ≥30%。

## Outcome

### 何が変わるか

**① レポート構造の転位**
F3.1 レポートが「**4体系の並列羅列**」から「**観察軸ベースの3層収束構造（整合・補完・矛盾）**」に変わる。同じ蟹座×ENFPユーザーでも、各セクションが harvest 結果に駆動されて固有性を持つ。

**② AC-1 の判定可能化**
F3.1 受け入れ基準 AC-1 が「統合考察1セクション以上（人間主観で判定）」から「**3セクション必須 × Positive/Negative Test 両方Pass**」に置き換わる。promptfoo で機械判定可能。

**③ 設計中枢の実装的接地**
設計中枢§2.3 パンチャ構造（4+1=5）が **コード（`lib/constitution/observation-axes.ts` 5軸 + `lib/diagnostics/integration/` ツリー収穫）として実体化**。これまで「哲学的宣言」だったパンチャ構造が、F3.1の動作に直結する技術仕様になる。

程度: F3.1 が出力する全レポートに対して上記が成立（部分対応ではなく100%）。

### 測定方法

**🤖 機械判定（Evalレイヤー / promptfoo / CI自動）— Positive と Negative を分離**

🔴 **Positive Test（引用は最低限、表現力は残す）**:
- 各セクション（整合・補完・矛盾）で `harvest.representative_keywords` から **最低3語以上** 引用
- 全体での引用率は **40〜60%** を目安（厳格な閾値ではなく観察用）
- 目的: harvest を無視して自由創作するのを防ぐが、自然文・独自表現の余地を残す

🔴 **Negative Test（ハルシネーションは厳しく）**:
- ツリーに存在しない **体系特徴語**（例: harvest外の星座固有特徴・MBTI機能名等の捏造）の混入率 **≤5%**
- 検証方法: 4体系の全特徴語彙集合を Deep Research 出力から抽出してホワイトリスト化、それ以外の体系語が出たら NG
- 目的: 「占星術ステレオタイプの権威化」「ツリー外捏造」を機械的に検出

🟡 **構造判定**:
- レポート出力に「整合 / 補完 / 矛盾」相当の3セクションが全て存在
- 5観察軸のうち最低3軸以上が harvest に出現

**📊 運用計測（F9.3 KPIダッシュボード / Phase 2 以降）**

- 🔴 F3.3「しっくりきた」マーカー利用率 各セクション **≥10%**
- 🔴 F3.4 満足度 **≥4.0**（PMF基準 / V1継承）
- 🟡 F4チャットでの harvest キーワード自発引用率 **≥30%**（V-4成功像の検証）
- 🟡 7日内再訪率 **≥30%**（設計中枢PMF基準）

**👥 定性（ユーザーインタビュー / Phase 2-3）**

- 「占いじゃなくて観察された」「自分のことが説明された」発話の検出
- 整合・補完・矛盾の3セクションの「腹落ち度」差分インタビュー

### 期限

**継続的に**（ユーザー判断）

- リリース後も恒常的に監視・改善
- スケジュール固定なし。「Tree of 4, Harvest 1.」設計原則は F3.1 の全リリースで不変（Constitution-as-Code として `lib/constitution/observation-axes.ts` で固定）
- Negative Test（ハルシネーション率 ≤5%）は commit ごとに CI で永続検証

### 最低ライン

**🔴 失敗ライン（下回ったら設計を見直す必須トリガー）**

| # | 指標 | 失敗ライン | 検出方法 |
|---|---|---|---|
| F1 | ハルシネーション率（ツリー外体系特徴語の混入） | **>5%（3回連続）** | promptfoo CI 継続実行 |

| F5 | 「占い」「鑑定」等の禁止語混入 | **>0件** | 言語設計テスト・即時停止 |

**🟡 警戒ライン（このラインを下回ったらレビュー対象）**

- F3.3「しっくりきた」マーカー利用率 5〜10%（10%目標に対する警戒域）
- F4チャット harvest 引用率 15〜30%（30%目標に対する警戒域）
- 観察軸網羅率 50〜67%（5軸中3軸=60%が目標、それ未満は要監視）

**設計判断トリガー（議論Turn4のリスクR1〜R5 由来）**:
- F1（ハルシネーション）が3スプリント連続で 5% 超 → Deep Research出力の汚染チェックを再実施
- F3.3 利用率が3スプリント未達 → F3.3 再設計（既存F3.3要件にも記載済み）

## Eval criteria

### 完成判定の3条件（全て満たして完成）

- [ ] **E-1-a 観察軸5軸が Constitution として固定されている**
  - `lib/constitution/observation-axes.ts` に5軸（`self_structure` / `relating_mode` / `motivation_energy` / `cognitive_style` / `embodied_pattern`）が定義済み
  - `lib/constitution/__tests__/drift.test.ts` で AGENTS.md・設計中枢ドキュメントとの整合が検証されている
  - えんまさ承認済み（Gate 2通過）

- [ ] **E-1-b ツリー生成→Harvest が動作している**
  - `lib/diagnostics/integration/` に `TreeBranch` / `IntegratedTree` / `HarvestNode` 型が定義済み
  - 4体系の診断入力（zodiac / animal / rokusei / mbti）から `IntegratedTree.harvest` の3層（integrations / complements / paradoxes）が生成される
  - Deep Research 由来のキーワードが `lib/data/` に commit 済み・えんまさ作成・専門家相談済み

- [ ] **E-1-c F3.1レポートが Harvest 駆動で生成され Eval Pass する**
  - `app/api/reports/generate/` のレポート生成プロンプトが harvest 結果を受け取り、整合・補完・矛盾の3セクションを必ず含むレポートを出力
  - **Positive Test**（各セクション最低3語引用）が CI で Pass
  - **Negative Test**（ツリー外体系特徴語混入率 ≤5%）が CI で Pass
  - Vercel OG (Satori) で縦長 1024×1792 即時生成成功（既存F3.1非機能要件継承）

### 失敗ケース（壊れていると判断する症状）

**🔴 B-1: 並列羅列への退化（最優先・本タスクの存在意義の否定）**
- 症状: 4体系の診断入力に対して、整合・補完・矛盾の3セクション構造が崩れ、「あなたは蟹座で〜、ENFPで〜、ペガサスで〜」と各体系を順番に説明するレポートが出る
- 検出: 構造判定テスト失格 / 目視レビューで「並列の塊」判定
- 対応: 統合アルゴリズム＝本タスクが機能していない。プロンプト・スキーマ・観察軸の見直し必須
- AGENTS.md対応: ③ UX断絶

**🔴 B-2: ハルシネーション（ステレオタイプ汚染）**
- 症状: harvest外の俗説特徴語が混入（「蟹座は家庭的だから尽くす女性」「ENFPは飽きっぽい」等）
- 検出: Negative Test で混入率 >5%
- 対応: Deep Research 出力の汚染チェック再実施 / プロンプトの引用ルール強化
- AGENTS.md対応: ① ロジック破綻

**🔴 B-3: 同一入力で異なる harvest（再現性破綻）**
- 症状: 同じ4体系入力に対して、harvest の3層分類結果が実行ごとに異なる
- 検出: Vitest unit test（同一入力テスト×10回）で harvest 構造の差分検出
- 対応: 統合アルゴリズムの決定論的設計の見直し（LLM温度設定・seed固定等）
- AGENTS.md対応: ① ロジック破綻

**B-1 が最も致命的**（タスクの存在意義を否定する）。B-2・B-3 は機能はするが品質劣化レベル。
