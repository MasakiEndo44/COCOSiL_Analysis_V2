## Turn 1｜現状認識・問題整理 — Procrustean Mapping 問題の診断

**桐谷**: Deep Research §5 の Hartmann et al. (2006) を見てください。4,000名以上の VES と 11,000名以上の NLSY1979 で「出生月・星座と Big Five・一般知能の統計相関はゼロ」が実証されている。にもかかわらず COCOSiL の現状設計は「zodiac × embodied_pattern」のように 1 体系を 1 軸に押し込む。実走ログでも aries の vector が positive → negative に転倒した。これは Haiku のバイアスというより、aries の本来の中核（火星支配の駆動性 = motivation_drive）を embodied 軸に強制マッピングしている **構造的歪み** の症状です。

**杏奈**: 仏教側からも同じ問題が見えます。Karunamuni (2015) の Five-Aggregate Model は五蘊を「動的情報処理プロセス」として再定式化したもので、本来「固定的なコンテナ」ではない。COCOSiL の 20 セル格子は、流動的な集積であるはずの五蘊を、固定的なラベリングの容器として誤用している。Boisvert (1995) や Hamilton (1991) の系譜から見ても、これは五蘊本来の用法から逸脱しています。

**桐谷**: 結論として、現状は「**Procrustean Mapping（プロクルステース的強制マッピング）問題**」と診断できます。プロクルステースが旅人を寝台の長さに合わせて切るか引き伸ばした神話の通り、各体系のカテゴリが本来持つ多次元の特徴量分布を、5 軸の格子に当てはめるために中核が削ぎ落とされ、副次的側面だけが残る。これはプロンプト改善では絶対に解消できない。

**みさき**: ん？つまり、水瓶座って本当は「自由を愛する」「友達多そう」「変わり者だけど博愛主義」みたいなイメージじゃないですか？それを「身体の気質」軸に閉じ込めちゃうと、「水瓶座 = むくみやすい」みたいな、誰も期待してない切り取り方になるってこと？

**杏奈**: 完全にその通りです、みさきさん。INTP も同じで、その中核は cognitive_style（想 = 概念化・抽象化）にあって、relational_mode は派生的側面。現状設計は「中核 vs 派生」の重み付けができず、20 セル全部に均等に情報を散らそうとする。結果、cognitive セルも relational セルも、両方が中途半端な記述になる。

**桐谷**: もう一つ重要な観点。Deep Research §1.3 が指摘する「五取蘊（pañcupādānakkhandhā）」の問題です。性格を「固定的実体」として捉えること自体が、仏教では苦しみの根源。COCOSiL の設計中枢は「無明を晴らす」と書かれているのに、現状設計は逆に「これが私だ」という執着（自己同一化）を強化するベクトルにある。**Procrustean Mapping は技術的問題であると同時に、哲学的整合性の問題でもある**。

> **Turn 1 診断**: ① Procrustean Mapping（中核 vs 派生の重み付け欠如） ② 五取蘊の固定化リスク ③ Hartmann 実証研究との非整合

## Turn 2｜選択肢の発散 — 5評価軸で4手法を配置

**桐谷**: 改修案を評価するために 5 つの軸を立てましょう。Deep Research §2 が挙げる 4 手法をこの軸の上に配置します。

| 手法 | ①意味保持 | ②動的表現 | ③計算コスト | ④PR #62 流用 | ⑤哲学整合 |
|---|---|---|---|---|---|
| A 共通次元マッピング (Big Five) | 低 | 極低 | 極低 | 低 | 中 |
| B 因子分析 (LPA) | 中 | 中 | 中〜高 | 低 | 中 |
| **C Embedding hierarchical** | **高** | **高** | **高** | **高** | **高** |
| D 部分改修（軸プロファイル化のみ） | 中 | 中 | 中 | 極高 | 中 |

**杏奈**: ①意味保持力で言うと、占星術の伝統的解釈（プトレマイオス『テトラビブロス』や Lilly『キリスト教占星術』）が持つ語彙的豊かさを Big Five に圧縮すると「金星座 = Agreeableness 高め」のような薄い記述になり、伝統が持つ「天秤座の腎・腰部対応」のような具体性が失われます。手法 A は最初に却下候補です。

**みさき**: でも待って、私からすると「Big Five でわかりました！外向性高めです！」って言われても、なんも腑に落ちないんですよ。星座とか動物占いとか、なんで好きかって、「あ、これ私だ」って思える具体的なディテールがあるからじゃないですか？それが消えたら、もう COCOSiL じゃなくなくないですか〜？

**桐谷**: みさきさんの指摘は決定的です。手法 C（Embedding hierarchical clustering）は、各体系の固有語彙を Sentence-BERT などで連続空間にマッピングし、共通の中核と固有の枝を保持できる。Deep Research §6 のコードサンプル（PTCD・PICEPR・ROCK）はすべてこの方向。さらに PR #62 のパイプラインは「Stage-Gated Generation」の構造を流用しつつ、Gate 3 に数値計算層を挿入するだけで済む。**捨てるものが少なく、得るものが大きい**。

**杏奈**: ⑤哲学的整合性で見ても手法 C が最も「諸行無常」に近い。階層クラスタリングの結果は「マージ距離」によって動的に変わるため、ユーザーの状況（時期・気分）が変われば distance も変わる、という運用が可能。Big Five のような固定スコアと違い、性格を「動的プロセス」として表現できる。

**桐谷**: 暫定オプションとして手法 D（部分改修）も覚えておきましょう。20 セル構造は維持しつつ、各カテゴリに「5 軸プロファイルベクトル」を追加し、軸ごとのプロトタイプ強度を 0-1 で表現。これだけで「水瓶座 = cognitive: 0.9, embodied: 0.2」と表現可能。Embedding 距離計算は次フェーズに回せる。

**みさき**: なんかこれって、星座と MBTI と動物占いと六星占術を「英訳して全部一緒にしよう」じゃなくて、「**それぞれの言い方を残したまま、共通する部分は太くしよう**」って話ですよね？確かにそっちの方が面白そう〜！

> **Turn 2 結論**: 本命は手法 C（Embedding + hierarchical clustering）、暫定オプションは D（軸プロファイル化）、A は却下、B は中間案として保留。

## Turn 3｜要件・範囲の確定 — 実需 → 3階層パターン → P0/P1/P2 優先度

**みさき**: 私が性格診断を受けるとき何を期待してるかちゃんと言いますね。① 「あー、私こういう人だわ」っていう **腑落ち感**（私の場合は MBTI が一番強い）、② 友達と比べて「あなたはこういう傾向、私はこういう傾向」って言える **違いの軸**、③ 仕事の進め方とか恋愛のクセとか、実生活で **使える具体的なアドバイス**。この3つです。

**杏奈**: みさきさんの実需を抽象化すると、3 つの認知レイヤーが見えます。

| 実需 | 認知レイヤー | プロトタイプ理論での対応 |
|---|---|---|
| 腑落ち感 | カテゴリ・アイデンティティ | プロトタイプの中心 |
| 違いの軸 | カテゴリ間距離 | プロトタイプ間距離 |
| 使えるアドバイス | 行動レベル具体化 | 行為頻度アプローチ（Buss & Craik 1983）の周辺エクセンプラ |

これは Rosch のプロトタイプ理論で言うところの「中心 → 周縁 → 行動エクセンプラ」の3階層に対応します。

**桐谷**: 3階層を「幹と枝」モデルの実装に落とすと優先度がはっきりします。

| 優先 | 改修項目 | みさきの実需との対応 |
|---|---|---|
| 🔴 P0 | カテゴリの5軸プロファイル化（手法 D 相当） | ①腑落ち感の改善 |
| 🔴 P0 | EMD ベース距離計算エンジン（TS 実装） | ②違いの軸 |
| 🟡 P1 | 階層クラスタリング（幹と枝の抽出） | ①+② の階層的説明 |
| 🟡 P1 | ナラティブ生成プロンプトの「幹と枝」対応化 | ③使えるアドバイス |
| 🟢 P2 | Triplet Loss による特性専用 Embedding ファインチューニング | 精度向上（将来課題） |

**杏奈**: もう一つ重要な制約を追加します。**「無我」整合性の観点から、出力ナラティブで「あなたはこういう人です」と固定的に断定しない設計が必須**。代わりに「あなたの行動には〇〇という傾向のパターンが見えます。これは状況によって変わります」という動的・確率的表現を強制する。プロンプトとシステム両方で。

**みさき**: ちょっとちょっと、それって例えば「水瓶座だから自由を愛する」じゃなくて、「**自由を求める瞬間が多めっぽい、特に〇〇な状況で**」って書くってこと？

**杏奈**: その通りです。仏教用語で言うと「諸行無常」を体験的に伝える書き方。チベット密教の「五部（五つの仏陀ファミリー）」の伝統でも、人は「金剛部の傾向が今は強い」のような時期的な表現で語ります。固定でなく波動として。

**桐谷**: 実装観点では P0 二つを Sprint 1 で、P1 を Sprint 2 で完了させる。P2 は実証データが集まってから。これでパイプラインのアーキテクチャ転換が現実的なスケジュールで進む。

> **Turn 3 結論**: 実需 3 つ → プロトタイプ理論 3 階層 → P0 / P1 / P2 優先度に分解。哲学的制約として「断定構文の排除」を追加。

## Turn 4｜技術深掘りとリスク検討 — 3つの法則の抽出

**桐谷**: P0-1「5軸プロファイル化」の実装を具体化します。`lib/data/categories/` 配下に体系×カテゴリ単位の JSON を配置:

```typescript
// lib/data/categories/zodiac-aquarius.json
{
  "system": "zodiac",
  "category": "aquarius",
  "axisProfile": {
    "embodied_pattern":   { "strength": 0.25, "features": ["末梢循環の不規則さ", ...] },
    "emotional_response": { "strength": 0.40, "features": ["距離を保つ感情処理", ...] },
    "cognitive_style":    { "strength": 0.90, "features": ["革新的思考", "客観性", "抽象化志向", ...] },
    "motivation_drive":   { "strength": 0.85, "features": ["自由志向", "独立への駆動", ...] },
    "relational_mode":    { "strength": 0.80, "features": ["博愛主義", "友愛", ...] }
  },
  "primary_sources": [...]
}
```

P0-2「EMD 距離計算」は TypeScript で `lib/diagnostics/integration/` 配下に実装。最初はユークリッド距離から、Sprint 2 で EMD（既存 `@stdlib/stats-incr-mvariance` 等）に置換。

**杏奈**: 技術リスクとして、Deep Research §8.2 が指摘する「**セマンティック・ドリフト**」は深刻です。LLM が「水瓶座の cognitive_style strength は 0.9」と判定する根拠が毎回揺れると、階層クラスタリングの結果も毎回違うツリーになる。これでは診断の再現性が崩壊します。

**桐谷**: そこで **法則①「決定論・非決定論の分離原則」** を立てます。具体的には：

- **静的データ層（決定論）**: 各カテゴリの軸プロファイル `strength` と `features` は、人間（えんまさ）が確定したデータとして `lib/data/categories/` に commit。LLM の毎回生成ではない
- **計算層（決定論）**: EMD 距離・階層クラスタリングは純粋な TypeScript 関数。同じ入力で同じ出力
- **ナラティブ層（非決定論）**: 計算結果（幹と枝）を受け取って LLM が文章化する部分のみ温度 0.3-0.5 で揺らがせる

これで「診断結果のロジック」と「表現の豊かさ」を両立できる。

**杏奈**: 次にリスク②、**バーナム効果**（Deep Research §8.1）。階層クラスタリングで「全員に当てはまる薄い中核」しか抽出されないと、結果は陳腐化する。これを防ぐには distance threshold θ の調整が鍵で、θ を厳しくすれば「太い幹」は減るが鮮明になり、緩めると逆になる。実証データで較正する必要があります。

**桐谷**: 解決策として **法則②「ゴールデンサンプルによる経験的較正」** を立てます。Sprint 1 で「ゴールデンサンプル 10 ペア」を用意：

- 直感的に近い性格組: INTP × 水瓶座、ESFJ × 蟹座、ENTJ × 山羊座 等
- 離れた組: INTP × ESFJ、ENTJ × 魚座 等

これらでクラスタリング距離を測定し、threshold を経験的に決定。

**みさき**: それ、私みたいな素人でも分かるテストってこと？「INTP の私と、ESFJ の友達は離れてるはず」を機械が当てたら OK？

**桐谷**: その通り、みさきさん。むしろ **みさきさんの「直感」がベンチマーク** になります。ヒラメ・えんまさ・みさきさんで投票して「これは近い」「これは遠い」のラベル付きデータを作る。素人の腑落ち感こそが、このプロダクトの最終評価軸です。

**杏奈**: 最後にリスク③、最大のもの。Deep Research §8.3 で警告されている「**無我との抵触**」と「**ハーバード成人発達研究との抵触**」。前者は技術的対処（断定構文の排除）で済むが、後者は relational_mode の格上げが必要です。現状は relational_mode を他軸と並列の1次元に置いていますが、ハーバード研究は「人間関係の質が幸福の唯一の決定因」を実証している。relational_mode を「**他4軸の相互作用の結果として顕現する最上位ダイナミクス**」として再定義すべき。

**桐谷**: つまり **法則③「4軸 + 1メタ層」階層原則**ですね。5 軸対等構造ではなく、relational_mode は他4軸の集約・相互作用関数として計算される派生軸。これは設計中枢の `META_LAYER` 概念（識を軸でなくメタ層として扱う）と同型構造になります。

**杏奈**: その通り。仏教の五蘊で識（vijñāna）がメタ層であるのと、relational_mode がメタ層であるのは、両方とも「他要素の相互作用が顕現したもの」という意味で構造同型です。これによって設計中枢のパンチャ構造解釈もより精緻になります。

> **Turn 4 法則**: ① 決定論/非決定論の分離 ② ゴールデンサンプルによる較正 ③ 4軸 + 1メタ層階層

## Turn 5｜方針統合・結論 — 設計3原則 → 5フェーズ修正計画

**桐谷**: 5 ターンの議論を 3 つの設計原則に集約します。

```
【ワードツリー構築 改修設計3原則】

① Profiles over Cells. — セルではなくプロファイル。
   4体系×5軸=20セルの格子を廃止し、各カテゴリに 5軸プロファイルベクトルを持たせる。
   各カテゴリは複数軸に分散した特徴量を保持する
   （例: 水瓶座 = cognitive 0.9, motivation 0.85, relational 0.80, embodied 0.25）

② Geometric Fusion, LLM Narration. — 幾何で統合、LLM で語る。
   統合は EMD + 階層クラスタリングという決定論的計算で。LLM は最終ナラティブ生成のみ。
   セマンティック・ドリフトの構造的解消 + コスト削減（推定 -55%）+ TTFT 短縮（15s → 5s）。

③ Anatta-Aware Output. — 無我を意識した出力。
   「あなたはこういう人です」と固定的に断定する表現を全プロンプトから排除。
   階層的「幹（複数体系合意の中核）」と「枝（特定体系固有の彩り）」として、
   状況依存的・確率的・動的な性格表現に。relational_mode はメタ層に格上げ。
```

**杏奈**: では具体的な次の一手をフェーズに分解しましょう。

**桐谷**: 修正計画は 5 フェーズ・合計約 23 営業日です。

| Phase | 期間 | 内容 |
|---|---|---|
| **A: データ層再構築** | Sprint 1 前半・5日 | `lib/data/categories/` 新設、4体系 100 カテゴリ分の軸プロファイル JSON 作成、`lib/constitution/category-profile-schema.ts` 新設、PR #62 の `lib/data/observation-tree/` 廃止判断 |
| **B: 計算エンジン実装** | Sprint 1 後半・5日 | `lib/diagnostics/integration/{distance,fusion-engine,trunk-branch}.ts` 新設、Vitest で INTP × 水瓶座等のサンプル組検証 |
| **C: PR #62 パイプライン改修** | Sprint 2 前半・5日 | `scripts/build-observation-tree/` を `scripts/build-category-profiles/` に改名、Step 2 抽出プロンプトを「カテゴリ × 5軸 strength」抽出に書き換え、Step 3 Schema 差し替え、Step 4 Critique も新スキーマ前提に |
| **D: ナラティブ層改修** | Sprint 2 後半・5日 | F3 統合レポート生成プロンプトを「幹と枝」入力前提に再設計、「無我を意識した出力」テンプレート構文確定、プレビュー主観テスト |

**みさき**: なんか最初は「20 セルの設計、強引じゃね？」って疑問だったけど、Deep Research でちゃんと裏付けされて、しかも「幹と枝」っていう私の最初のイメージそのまま実装できるってわかってめっちゃ気持ちいい〜！しかも「**あなたはこういう人**」じゃなくて「**こういう傾向が今強め**」っていう書き方になるのって、自己理解ぽさが出ますよね。これが「他のと違うってこういうこと」ってわかった感じです。爆上がり〜！

**杏奈**: みさきさんの最後の発言が、まさにこの改修の本質を捉えています。COCOSiL は「無明を晴らす」プロダクトとして設計中枢に置かれているわけですが、現状設計は皮肉にも自己同一化（無明の温存）を助長する方向にあった。「幹と枝」モデルへの移行は、技術的改修であると同時に、**設計中枢の哲学への忠実度を高める改修**でもあります。

**桐谷**: 計算コスト面でも、Deep Research §7.4 が示す通り LLM トークン消費 -55%、TTFT 15 秒 → 5 秒未満を達成可能。投資対効果は明確。承認いただければ、Sprint 1 の フェーズ A・B から着手します。

## ✅ 議論まとめ

| 項目 | 方針 |
