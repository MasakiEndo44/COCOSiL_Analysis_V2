## Turn 1｜現状認識 — 「公式 vs 派生」の伝言ゲーム問題

**久保田**： まず事実から始めます。lib/data/animal-characters.ts は **「個性心理学研究所」公式の 60 体リスト** で、ID 1-60 に正確な公式呼称が紐づいています。例えば ID 4 は **「フットワークの軽い子守熊」**（コアラではなく **子守熊**）、ID 29 は **「チャレンジ精神旺盛なひつじ」**。一方、Q5b-1 / Q5b-2 で私が Deep Research プロンプトに書いた呼称は、Web 上の派生資料・解説サイトに頼った結果、**「落ち着きのある狼」「強靭な狼」「リーダーとなるチータ」「気分屋のペガサス」など公式リストに存在しない名前** を含んでしまった。

**西園寺**： これは知識グラフ設計の典型的な **Canonical Naming Drift** 問題です。一次資料（公式リスト）が存在するのに、二次資料（解説サイト・書籍の派生）からプロンプトを組んだため、**Canonical Name と呼ばれる正本名から離れた表記** が DR 結果に流入した。私の経験では Wikidata と DBpedia の alignment でも同じ現象が起きます — Web 解説で広まった通称名を、機械的にデータ統合の主キーに使うと、本来の表記との照合が崩壊する。

**みさき**： え待って、それって私で言うと、私が亥年で「子守熊系」なんですけど、もし診断結果に「フットワークの軽い**コアラ**」って出てきても **「あ、子守熊のことね」って読み替え** できるけど、システム的には「全くの別キャラ扱い」になっちゃうってこと？

**久保田**： みさんの理解は正確です。**人間は「コアラ ≈ 子守熊」と同一視できますが、データ層では完全に別の文字列キー**。私の Q5b で書いた「フットワークの軽い**こあら**」と公式「フットワークの軽い**子守熊**」は、機械にとって 1 文字違いでなく **別キャラ**。これが 60 体中 ~20 体で発生しているため、Q5b で集めた特徴語 480 語のうち、**公式 60 体に正しく貼り付けられるのは推定 60% 強**。

**西園寺**： もう一段抽象化します。これは結局 **「Source of Truth の明確化なくして、葉ノードデータ収集を進めるべきでなかった」** 問題。Layer 1-3（幹）は学術文献に直接根拠を持っていたが、葉ノードの **正本ソース（個性心理学研究所の公式リスト）の存在確認を Q5b 設計時にスキップ** したのが構造的欠陥。

**久保田**： 診断としては：**「Q5b プロンプト設計時に lib/data/animal-characters.ts という社内既存正本を参照せず、Web 派生情報に頼ったため、約 40% の呼称が公式リストに存在しない or 表記差分を含む」** が論点です。

> **🩺 Turn 1 診断**: Canonical Naming Drift 問題 — 公式正本を参照せずに Web 派生情報で Q5b プロンプトを組んだため、60 体中 ~30 体で呼称差分・存在しないキャラ生成が発生。

## Turn 2｜選択肢の発散 — 統一戦略 3 案

**久保田**： 統一戦略の選択肢を発散させます。4 つの評価軸：(a) Q5b 投資の保全 / (b) 公式呼称への忠実度 / (c) 追加 DR コスト / (d) 実装後の保守性

**西園寺**： 3 案を並べます：

| 案 | 戦略 | (a) 保全 | (b) 忠実度 | (c) 追加 DR コスト | (d) 保守性 |
|---|---|---|---|---|---|
| **A. 全面リネーム + 不足分 DR 再実行** | Q5b を公式整合させ、不存在キャラは Q5b-3 補完 | △（40% 破棄） | ⚪️ | △ | ⚪️ |
| **B. マッピング表で吸収（alias）** | 公式 ↔ 派生の alias 表で吸収 | ⚪️ | △ | ⚪️ | △ |
| **C. ハイブリッド: 表記差分は吸収、不存在キャラのみ Q5b-3 補完** | regex 自動正規化 + 18 体補完 | ⚪️ ~75% | ⚪️ | 🟡 | ⚪️ |

**みさき**： 案 A は **40% も破棄するのもったいなくない？** あと案 B は「私のコアラ呼称 → 公式の子守熊呼称」みたいな表が増えるってこと？それメンテ大変そう〜。やっぱり **案 C** が一番バランス良さそう？

**久保田**： みさんの判断が筋です。**案 C が 4 軸でバランス最良**。表記差分は機械的正規化で吸収できるので、約 40% は救済可能。完全に存在しないキャラのみ Q5b-3 で補完。

**西園寺**： 技術的にも案 C 推奨。**Levenshtein Distance や Jaccard Similarity** で機械的にマッチング、similarity > 0.7 なら自動正規化、それ未満は手動判定 or Q5b-3 補完。

> **🎯 Turn 2 選択**: 案 C「ハイブリッド」を採用。表記差分は機械的正規化で吸収、完全不存在キャラのみ Q5b-3 で補完収集。

## Turn 3｜実需と正規化ルールの優先度

**みさき**： 私が亥年だと **「コアラ」って言われたり「子守熊」って言われたりするの、正直どっちでもいい** んですよ。「私のキャラが特定できれば」あとは何でもいい。逆に「ペガサスです」って言われた後に **「これは落ち着きのある狼の話なんですけど〜」** って始まったら **「え？私狼だっけ？」って混乱** する。

**久保田**： みさんが言っているのは、**正規化の粒度 (Normalization Granularity)** の優先順位ですね：

1. **R1: キャラ同定の正確性**（私のキャラが何かを誤らないこと）が最重要
2. **R2: 表記の揺らぎ吸収**（こあら/子守熊レベル）は許容
3. **R3: 特徴語の出典明確性**

**西園寺**： 正規化ルール 4 段階：

| 優先度 | ルール | 例 | 自動化可否 |
|---|---|---|---|
| 🔴 P0 | 漢字 ⇄ ひらがな差分 | こあら → 子守熊 | ✅ 自動 |
| 🔴 P0 | 送り仮名差分 | 持った → もった、良い → いい | ✅ 自動 |
| 🟡 P1 | 「の」差分 | 面倒見の良い → 面倒見のいい | ✅ 自動 |
| 🟢 P2 | 完全不存在キャラ | 「落ち着きのある狼」「リーダーとなるチータ」等 | ❌ 手動 / Q5b-3 補完 |

> **🎯 Turn 3 優先度**: P0 = 表記差分の自動正規化 / P1 = 「の」差分の自動吸収 / P2 = 完全不存在キャラは手動マッピング判定または Q5b-3 補完

## Turn 4｜技術深掘り — 不一致 60 体の分類と Q5b-3 設計

**久保田**： 私の使った呼称と公式 60 体を 1 体ずつ照合した結果、**3 つのカテゴリ** に分類：

| カテゴリ | 件数 | 例 |
|---|---|---|
| **完全一致** | 約 30 体 | ネアカの狼、穏やかな狼、しっかり者のこじか、落ち着きのない猿、長距離ランナーのチータ、愛情あふれる虎、社交家のたぬき、磨き上げられたたぬき、デリケートなゾウ、物静かなひつじ、落ち着きのあるペガサス 等 |
| **表記差分のみ**（自動正規化で救済可） | 約 12 体 | フットワークの軽いこあら → **子守熊**、母性豊かなこあら → **子守熊**、強靭な翼を持つペガサス → **もつ**、面倒見の良い黒ひょう → **いい**、大きな志を持った猿 → **もった** 等 |
| **完全不存在 / 取り違え** | 約 18 体 | 落ち着きのある狼（公式不在）、強靭な狼（公式不在）、リーダーとなるチータ（公式「リーダーとなるゾウ」）、感情豊かなライオン（公式「感情**的な**ライオン」）、気分屋のペガサス（公式「気分屋の**猿**」）、協調性のあるひつじ（公式「協調性の**ない**ひつじ」、意味逆転）等 |

**西園寺**： 技術的に深掘り：

- **完全一致 30 体** → そのまま `twigs/animal.ts` に投入可
- **表記差分 12 体** → regex スクリプトで救済（5 行程度）
- **完全不存在 18 体** → Q5b-3 として公式 60 体ベースの不足分のみを補完 DR。語数 18 × 8 = 約 144 語

**みさき**： Q5b-3 ってめっちゃ短くて済むんですね！全体的にはあと **1 セッションだけ追加** で 60 体完全に揃うってこと？

**西園寺**： その通り。**Q5b-3 こそが「公式正本を最初に渡す」設計** にすべき。

**久保田**： 4 つの **抽象法則**：

> **法則 1: Source of Truth First, Always.** — 葉ノードデータ収集の前に、社内に既存の Canonical List がないか必ず確認する。
>
> **法則 2: Web Derivatives Drift, Official Sources Don't.** — Web 上の派生資料は呼称が drift しがち。一次資料（公式リスト）を必ずプロンプトに埋め込む。
>
> **法則 3: Machine-Normalizable Differences are Recoverable, Naming Drift is Not.** — 表記差分は救済可能、固有名 drift は再収集必要。
>
> **法則 4: 5-Line Regex Saves 100 Lines of Manual Mapping.** — 正規化は regex の方が alias table より保守容易。

> **🎯 Turn 4 法則**: Source of Truth First / Web Derivatives Drift / 機械正規化と固有名 drift の区別 / regex over alias table

## Turn 5｜方針統合 — 公式呼称統一 5 原則 + 即実行アクション

**久保田**： **公式呼称統一 5 原則**：

> **④ Embed Canonical List in DR Prompts.** — 今後の DR では公式正本リストをプロンプトに埋め込み。

**みさき**： 「30 体はそのまま使えて、12 体は機械が直してくれて、残り 18 体だけもう一回 DR する」ってことですよね？それなら **来週中に 60 体完全に揃う** じゃないですか〜！しかも今後は「公式リストを最初にプロンプトに入れる」って決めたから、もう同じミス起こらない！
